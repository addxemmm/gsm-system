# Reliability audit and release / 可靠性审计与发布

## Scope / 范围

Go management API, child-process lifecycle, native SQLite configuration and
subscriber writes, Docker startup/persistence, and Windows-to-SDR deployment.
The legacy Python archive and radio algorithms are not rewritten. Analysis used
GPT-6 astra (xhigh); bounded implementation workstreams used GPT-5.6 sol (xhigh),
with the primary session integrating, reviewing and validating the release.
范围包括 Go 管理 API、进程生命周期、原生 SQLite 配置与签约写入、容器持久化及部署脚本。
未重写旧 Python 档案或射频算法。使用 astra 极高独立审计、sol 极高分工实现，由主会话集成与验收。

## Confirmed defects and changes / 已确认缺陷及改动

| Priority / 优先级 | Defect / 缺陷 | Resolution / 修复 |
|---|---|---|
| P1 | OpenBTS had no successful-path `Wait`; dead children remained reported as running. 成功启动后未回收，进程退出仍报运行。 | Single reaper and completion-based status. 唯一回收者及退出信号状态。 |
| P1 | SIGKILL reused an expired TERM context. 强杀复用已过期的温和停止超时。 | Independent termination budgets and regression tests. 分离超时并补回归测试。 |
| P1 | Startup swallowed service errors and ignored cancellation; partial starts leaked children. 忽略依赖错误和取消，失败后遗留进程。 | Owned-process rollback, cancellable readiness and bounded CLI operations. 按本轮进程回滚、可取消就绪等待、有界 CLI。 |
| P1 | Presets committed eight updates separately and raced startup. 预设八项分别提交，与启动交错。 | One guarded SQLite transaction and lifecycle lock; legacy API uses the same manager. 单一带行数检查的事务及生命周期锁，旧接口复用同一实现。 |
| P1 | Subscriber writes ignored database errors and returned success after partial updates. 签约写入忽略错误，部分失败仍报成功。 | Related writes share a transaction; database failure reaches the API. 相关写入共用事务，数据库失败正确返回。 |
| P1 | Entrypoint overwrote the subscriber registry; container replacement lost native databases. 入口脚本覆盖签约库，重建丢原生数据库。 | Persist native directories under `/data/state`, seed only absent databases, reject damaged state. 原生目录迁入持久卷，仅缺失时初始化，异常数据停止启动并保留。 |
| P1 | Image archive disabled Asterisk ODBC realtime. 镜像归档配置禁用 Asterisk ODBC realtime。 | Enable the module in the UHD4 image layer without modifying the legacy archive. 在 UHD4 镜像层启用，旧档案不改。 |
| P2 | Oversized/trailing JSON was misclassified or accepted; panic/auth failures lacked audit correlation. 超限或尾随 JSON 误处理，异常及鉴权失败缺审计关联。 | Full-body object validation, HTTP 413, correlated recovery/audit and bearer comparison hardening. 完整对象校验、413、异常/鉴权审计及令牌比较加固。 |
| P2 | Deployment swallowed native exit codes and built the obsolete compose by default. 部署吞退出码，默认构建旧配置。 | Checked commands, unique temporary staging, UHD4 default, explicit compose/project selection and offline tests. 检查退出码、独立临时目录、正确默认及离线测试。 |
| P2 | Go 1.22 was still used for deployed binaries. 部署二进制仍使用旧 Go 1.22。 | Pin Go builder to 1.26.8; retain 1.22 source-compatibility CI. 构建器固定 1.26.8，CI 保留源码兼容检查。 |

Go's maintained-release policy and 1.26.8 release are documented in the
[official release history](https://go.dev/doc/devel/release).
Go 维护窗口及版本信息见上述官方来源。

## Upgrade contract / 升级约束

- Back up all four native databases with SQLite `.backup` before replacing the
  old container; retain a separate timestamped backup. Pause cell operations and
  management writes during the snapshot/cutover. See [DEPLOY](DEPLOY.md).
  替换前备份全部四份数据库，并保留独立时间戳备份；备份及切换期间暂停小区操作与管理写入。
- Use the existing data volume and a distinct Compose release project so the
  old stopped UHD4 container remains available. No volume removal or image prune.
  复用现有卷，用独立发布项目保留旧停止态容器；不删除卷，不清理旧镜像。
- Recreating the management container does not start RF transmission. Hardware
  discovery is not part of the periodic container health check.
  重建管理容器不自动发射；周期健康检查不调用硬件探测。
- The pre-existing uncommitted Asterisk archive edit is preserved separately;
  the deployable fix lives in `Dockerfile.uhd4`.
  原有未提交的 Asterisk 档案改动单独保留；可部署修复位于 Dockerfile。

## Remaining risks and acceptance limits / 剩余风险与验收边界

1. **API authentication is optional.** Compose now forwards `GSM_API_TOKEN` and
   configurable listening address, but does not silently rotate existing clients'
   credentials. The observed deployment had no token and listened on all interfaces.
   Use a host-only secret and restrict the management network before exposing it.
   **鉴权仍为可选项。** 已修复 Compose 的令牌传入能力，但不静默更换现有客户端凭据。
   观察到原部署未设令牌且监听全部网卡；对外暴露前应配置专用密钥与管理网访问限制。
2. **SMS history logging is not connected in the observed runtime.** No
   `/data/log/smqueue.log` or `/dev/log` socket was present. The API parser tests do
   not prove live SMS delivery/history, which still needs a validated log pipeline.
   **现网短信历史日志链路缺失。** 未见对应日志文件或 syslog socket；解析器测试不等于
   实际短信收发与历史验收，需要后续接通并验证日志链路。
3. **RF/UE/SMS/voice are not inferred from API health.** Active transceiver device
   ownership can make a second UHD discovery report no free device. Full attach,
   SMS and voice verification needs the actual test handsets and a deliberate RF run.
   **API 健康不等于无线全链路验收。** 收发器独占硬件时二次探测可能无空闲设备；
   入网、短信和通话仍需测试手机及明确的射频测试过程。
4. **Upstream native stack remains legacy.** OpenBTS 5.0/UHD 4.1, privileged USB
   access and host networking remain architectural constraints, not eliminated by
   this reliability patch. No claim of exhaustive vulnerability clearance is made.
   **原生协议栈仍旧。** OpenBTS/UHD 版本、特权 USB 与 host 网络仍为架构约束；
   本次可靠性修复不代表已排除全部漏洞。
   **2026-09-08 update / 后续更新:** the new Compose deployment replaces host
   networking with a single bridge and publishes only TCP 8082; privileged USB
   access and the legacy native stack remain. 新版已改为单 bridge 并仅映射 TCP 8082，
   特权 USB 与旧原生栈仍保留；此更新不改写上面的历史观测。
5. **SQLite transaction scope:** SQL-error rollback is tested; multiple attached
   databases in WAL mode are not a cross-file power-loss atomicity guarantee.
   **SQLite 事务边界：**验证 SQL 错误回滚，不将 WAL 下多数据库事务描述为断电时跨文件原子保证。
6. **Vendor reproducibility:** `prefetch_vendor.sh` still treats an existing source
   directory as complete, and several native dependency revisions are not locked.
   The release reused the existing server-side native build cache; it is not a
   fresh-from-zero verification of every upstream native dependency.
   **依赖复现性：**源码预取仍把“目录存在”视为完成，部分原生依赖未固定提交；本次复用已有
   原生构建缓存，不将结果描述为全部上游依赖从零重建已验证。
